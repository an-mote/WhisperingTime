# 印迹产品功能与设计说明

更新日期：2026-10-16。本文记录已确认的新产品方向；原型实施与实际验收见[SwiftUI原型验证](../开发/SwiftUI原型验证.md)。旧 Flutter 能力及测试不会自动继承到 SwiftUI。

## 产品定位

印迹是一处回顾生活内容的地方。打开应用先看见已经留下的印迹，需要时再补记。记录是一种为未来回顾积累素材的动作，不设置每天必须完成的任务。

“轻、易懂、入门快”落实为：无需账号即可进入本地原型；不要求先建分类、写标题或配模板；首页不被功能面板和录入表单占据；高级内容按需添加。原型提供独立只读示例，用户测试资料另存，不将示例混入个人资料。

## 一份内容，四种回顾

| 形式 | 主要用途 | 行为 |
| --- | --- | --- |
| 卡片 | 快速浏览画面和片段 | 首页默认形式；展示文字、图片和声音线索，进入后可完整阅读。 |
| 日历 | 按日期寻找内容 | 保留年、月、星期和日期坐标；没有记录的日期不显示缺席或失败状态。 |
| 时间轴 | 串联不同生活分支 | 时间从左向右推进，分类向上下展开为树根式分支，压缩无记录间隔。 |
| 播放 | 沉浸地逐条回顾 | 应用内逐页、全屏、前后翻页和可选自动播放；不生成 PowerPoint 文件。 |

四种形式共用分类范围和选中内容，切换不重新开始。卡片和时间轴可浏览全部印迹，也可只看一个分支及其后代。播放默认手动；方向键翻页、空格播放／暂停、Esc 退出。长文可滚动，用户主动播放声音时暂停自动翻页；应用失活时暂停自动播放。

默认隐藏时间，用户可选择绝对日期或相对时间。发生时间仍保存在资料中，不因隐藏而丢失；日历保留必要坐标，时间轴底部始终保留导航所需的年月刻度。不开设连续记录天数、缺席天数、断签提醒或“重新开始”压力文案。这些是设计取舍，降低内疚的实际效果仍需真实使用验证。

### 树根式时间轴

时间轴是一幅可横向、纵向浏览的分支画布。较早内容在左，较新内容在右，各分类共享时间横坐标。每个分类及其后代在纵向连续排列，兄弟分类依次展开，不能为了压低画布高度而把不同子树的内容穿插在一起。多个顶层分类与未分类分别展开；浏览某个分类时只呈现该分类及其后代。

分类名称使用统一的语义字号，靠近所属分支及首篇；不显示级别编号，不新增包围分类子树的分组框。分类关系通过稳定排列、相邻位置和必要连线保持易读，不依靠连线颜色猜测归属，不设置远离内容的独立左侧分类栏或结构走廊，也不改变内容的时间位置。

每篇印迹只在所属分类出现一次，每支第一篇印迹直接作为连接点，点击即可阅读，不另设空连接圆点。父子分类均有直属内容时，从父分类真实首篇卡片边缘分叉，直接连到子分类真实首篇卡片边缘；子分类首篇较早时允许向左回接，不改动内容日期，也不把分叉挪到空白处。亲子连线优先采用局部短曲线，必要时经过对应子树边界的窄通道，不交叉、交织或穿过其他分支；同分类的后续内容使用简单平直的连接。共同父节点处的真实分叉应清楚可辨，不能靠换色掩盖线缆纠缠。

没有直属印迹、但后代有内容的祖先分类，以靠近后代的紧凑分类名称与位置表达归属，不增加分组框，不逐支绘制额外的关系缆线，不添加空内容点或额外长连线；不分配空内容行，也不延伸没有内容的悬空尾巴。整个分类及其后代均无内容时不占画布。

节点展示紧凑摘要与图片、声音线索，完整内容在现有阅读面板中打开。横向按发生时间排列，同时间内容稳定错位，同支卡片不得重叠。在保持子树顺序稳定、分类关系易读和连线不交叉的前提下紧凑排布，压缩没有记录的时段，避免以空白距离强调中断；本轮不提供缩放或手动调整分支。

底部固定时间导航条，可拖动滑块连续移动画布，画布滚动也同步更新滑块。滑块宽度表示当前可见范围，导航保留纵向位置；内容不足一屏时停用横向导航。另提供较早／较新按钮和键盘入口。滚动只改变视口，不自动改变选中内容或打开阅读面板。

切换回顾形式或分类范围时保留选中上下文和时间轴视口；其他形式选中新内容后，回到时间轴定位该篇，否则恢复原位置。首次进入从最早内容开始。

验收资料须包含多个兄弟分类各有子孙的多层树、无直属内容的祖先、父子时间倒置、未分类及长时间范围。实际窗口中既要确认内容唯一、卡片不重叠，也要逐级确认祖先归属，并检查连线之间没有非预期交叉、重合和绕入其他子树；只检查连线未穿卡片不能判定通过。

## 分类是一棵可整理的树

以一种分类节点替代“主题”和“分组”两种固定概念。节点可包含子节点和印迹，层级不固定；每条印迹可以不分类，也可以归入一个分支。父分支汇总后代，首页“全部印迹”跨分支串联。

例如：人生 → 家庭生活 → 个人生活 → 饮食，人生 → 职场 → 某段项目经历。这只是使用示例，不预置为必须遵守的目录，也不要求用户理解整棵树后才能记录。

分类支持创建、改名和移动。移动不得形成循环；删除一个分类时，将子分类和印迹移到其父级，顶层印迹归入未分类，内容本身不随分类删除。按钮和菜单提供全部操作，不依赖精确拖动。

## 补记：先输入，再按需补充

标题与归属可选，默认进入纯文字编辑。没有标题时，界面用正文首行作摘要，不把摘要写成标题；仅有图片或声音的印迹也可存在。

| 内容 | 原型行为 |
| --- | --- |
| 文字 | 默认输入方式，保留中文与长文，标题可空。 |
| 图片 | 系统文件选择器导入，复制到独立附件目录后引用；不依赖原文件继续存在。 |
| 语音 | 麦克风录音或导入音频，保留原声、回放和可编辑转写。 |
| 转写 | 使用 macOS 26+ 设备端 SpeechAnalyzer／SpeechTranscriber；原声先保存，识别随后完成，失败可重试或手动补充。 |
| 刻度 | 名称、文字／数值／选项及可选单位，按需展开，不要求先建模板。 |

录音时才请求麦克风权限；导入音频不需要麦克风权限。中文模型未就绪时提供明确准备入口；下载系统识别模型与上传录音不同。原型不增加联网转写分支，不将占位文字冒充识别结果。

macOS 26+ 是系统最低要求，不保证所有硬件都支持设备端转写；应用另行检查系统能力与语言模型。录音还需要可用的音频输入设备，没有麦克风时可导入音频或直接补充文字。

保存成功以本地持久化为准。失败保留输入和已导入原声；关闭编辑或退出应用时保护未保存内容。识别结果不能覆盖用户已经编辑的转写。语音、图片、刻度和正文都属于回顾素材，不强制每条填全。

## 本地原型与正式资料库

本轮为独立本地交互原型，使用版本化 JSON 与附件目录，独立标识 `com.acered.whisperingtime.prototype`。分类、印迹与附件使用稳定标识；原子提交后才报告保存成功；损坏或未知版本资料阻止空白覆盖。

原型资料尚未做内容加密，也不接旧账号、钥匙串、Go 服务或旧 `.wtbackup`。不把原型当作正式加密资料库；旧版可靠性与备份报告保留为后续实现合同，正式版本须独立重新验收。

## 多端同步：临时中转

设备本地是资料主本，服务器只传递变化。接收设备必须验证、解密并将正文和所需图片／原声持久化之后才确认；仅下载成功或显示在界面不算完成。

- 每次中转从服务器完整接收内容及附件起最多保存 **365 天**。全部目标设备确认后提前删除；重试、下载或重启不延长期限。
- 到期仍未收齐时删除该次中转载荷。离线设备返回后保留本机修改，并从另一台完整设备或用户备份补齐，不能错误显示“全部同步”。
- 新设备首次同步需要已有完整设备提供历史快照；服务器可能已经清空历史内容，不能承担历史资料库。
- 移除失联设备必须由用户明确操作。冲突保留双方内容；未来协议需定义幂等、乱序、墓碑、分类移动冲突及附件确认。
- 中转不是备份。所有设备遗失且没有用户备份时，已经投递并删除的内容无法找回。

删除承诺限于验收过的存储边界。未来必须检查在线对象、临时文件、日志、对象版本和备份策略；账号／设备登记等必要元数据与中转内容分别说明。本轮不实现这些服务端行为。

原型仅演示“等待设备接收”“全部接收，中转已清除”“已到期，需从其他设备补齐”“首次补齐”，每处明确标注演示。现有 Go 服务仍依赖长期保存的 PostgreSQL 和 MinIO，不能通过删除旧数据直接变为新中转服务。

## 设计与后续顺序

采用克制的 Mac 原生界面、系统中文字体、语义颜色与可收起侧栏，内容画布占主要空间。旧 logo 及候选稿删除，本轮不创作新 logo。具体规则见[UI设计规范](../设计资产/当前界面/UI设计规范.md)。

先用原型验证“看见内容 → 换一种方式回顾 → 按需补记”的流程，再推进正式本地资料库、加密与独立备份，最后实现真实设备中转。AI、社交、支付及其他平台发布继续延后；设备端语音转写是已确认的录入能力。
