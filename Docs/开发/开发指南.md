## Flutter 与 Dart 环境

2026-10-14 核查的 stable 版本为 Flutter `3.47.7`，随附 Dart `3.13.5`。项目要求 Dart `>=3.13.5 <4.0.0`、Flutter `>=3.47.7`；后续升级前应重新核对版本及项目兼容性。版本可从 [Flutter 官方归档](https://docs.flutter.dev/install/archive)和 [Homebrew Flutter cask](https://formulae.brew.sh/cask/flutter)查询。

Flutter SDK 已包含 Dart SDK，使用 Flutter 提供的 `dart` 命令即可，避免再安装独立 Dart 导致路径冲突。[Dart 官方安装说明](https://dart.dev/get-dart)

### 安装与升级

本机使用 Homebrew 管理 Flutter 和 CocoaPods。首次安装：

```bash
brew update
brew install --cask flutter
brew install cocoapods
```

已安装时，更新 Homebrew 并升级：

```bash
brew update
brew upgrade --cask --greedy flutter
brew upgrade cocoapods
```

Flutter cask 标记为可自行更新，`--greedy` 会将它纳入 Homebrew 升级范围。[Homebrew 命令说明](https://docs.brew.sh/Manpage#upgrade-options-installed_formula-installed_cask-)

本机为 Apple Silicon，Homebrew 前缀是 `/opt/homebrew`：Flutter SDK 安装到 `/opt/homebrew/share/flutter`，`flutter` 与 `dart` 命令分别链接到 `/opt/homebrew/bin/flutter` 和 `/opt/homebrew/bin/dart`。其他机器应以自己的 `brew --prefix` 和命令路径为准。

下载需要代理时，先查看实际系统配置：

```bash
scutil --proxy
```

读取已启用的 HTTP、HTTPS 或 SOCKS 代理地址与端口，不把本机端口作为项目默认值。将下方占位值替换为实际 HTTP、HTTPS 代理后，可以仅为单次安装命令设置环境变量；不需要代理时直接使用上面的安装命令。[Homebrew 代理说明](https://docs.brew.sh/Manpage#using-homebrew-behind-a-proxy)

```bash
env http_proxy="http://<HTTP代理主机>:<端口>" \
    https_proxy="http://<HTTPS代理主机>:<端口>" \
    brew install --cask flutter
```

仅有 SOCKS 代理时，可按实际配置使用 `all_proxy="socks5://<SOCKS代理主机>:<端口>"`。

### macOS 工具链与验证

macOS 构建需要完整 Xcode 和 CocoaPods。本机 Xcode `27` 位于 `/Applications/Xcode.app`，shell 配置使用以下开发者目录；其他机器按实际 Xcode 位置调整。[Flutter macOS 配置说明](https://docs.flutter.dev/platform-integration/macos/setup)

```bash
export DEVELOPER_DIR="/Applications/Xcode.app/Contents/Developer"
```

安装完成或调整 `~/.zprofile` 后，打开新终端加载 shell 配置；也可以在当前终端执行 `source ~/.zprofile`。确认 Homebrew 的 `bin` 已在 `PATH` 中，然后验证命令来源、版本与工具链：

```bash
command -v flutter
command -v dart
flutter --version
dart --version
flutter doctor -v
```

根据 `flutter doctor -v` 的结果处理目标平台的工具链问题，再执行项目命令。以上为安装和验证操作说明，实际安装、构建与启动结果以执行记录为准。

本次升级到 Flutter `3.47.7` 时，工具自动将 macOS 最低部署版本迁移为 `12.0`，并加入 Swift Package Manager 集成。`flutter_secure_storage_macos` 和 `isar_flutter_libs` 仍通过 CocoaPods 集成，因此 macOS 开发环境仍需安装 CocoaPods。

本地 `Runner` 的 Debug 配置采用 ad-hoc 签名（identity 为 `-`），无需 development profile。原 `DebugProfile.entitlements` 中的空 `keychain-access-groups` 阻挡了本地构建，因此 Debug 改用新增的 `macos/Runner/DebugLocal.entitlements`：保留 sandbox、JIT、双向网络和用户选择文件只读权限，移除空 keychain 分组。Profile 和 Release 继续使用各自原有的权限文件及签名配置。

2026-10-14 本机已安装 Flutter `3.47.7`、Dart `3.13.5` 和 CocoaPods `1.17.0`。`flutter pub get` 成功，`flutter analyze --no-pub` 零问题。`flutter run -d macos --no-pub` 构建成功并启动 Dart VM 和 Isar；退出开发命令后，通过 `xcodebuildmcp macos launch` 再次确认应用启动，验证完成时应用独立运行。`codesign --verify --deep --strict` 通过，签名为 `adhoc`。

升级阶段仅验证 macOS，Android SDK 和 iOS simulator 尚未安装。插件原生编译仍有 warning，上述两个插件仍依赖 CocoaPods。升级阶段未完成视觉验证；后续界面重设计使用生产 Flutter 组件渲染检查，范围见下方说明。升级日志保存在根目录 `TMP/Flutter升级/2026-10-14/`。

## Flutter 应用

先确保本机已安装 Flutter SDK，并具备目标平台所需的开发工具。进入工程目录，安装依赖并执行静态分析：

```bash
cd App/WhisperingTime
flutter pub get
flutter analyze
```

列出可用设备，然后在 macOS 上启动应用：

```bash
flutter devices
flutter run -d macos
```

其他目标设备使用其实际设备标识：

```bash
flutter run -d <设备标识>
```

根据发布目标选择构建命令；例如 Android 或 macOS：

```bash
flutter build apk
flutter build macos
```

各平台构建需要对应平台工具链。上述命令用于说明新目录下的操作入口，不表示所有平台已经完成构建验证。

## 界面设计与验证

当前视觉与交互规则见 [UI设计规范](../设计资产/当前界面/UI设计规范.md)。共享主题和组件位于 `lib/design/`，页面从主题读取语义颜色；浅色、深色、高对比及减少动画使用系统偏好。

Flutter 工程中的 `UIQA/` 保存生产组件的界面测试。测试使用内存样本，避免真实账号提交、服务端写入和媒体上传，覆盖欢迎与表单、主题分组、记录浏览、日历、筛选和编辑等界面。执行：

```bash
cd App/WhisperingTime
flutter analyze --no-pub
flutter test UIQA --no-pub
flutter build macos --debug --no-pub
```

截图与执行日志输出到根目录 `TMP/UI重设计/2026-10-14/`。测试直接渲染正式组件与 `AppTheme`，并补充中文、拉丁字符和 MaterialIcons 字体。本机 Flutter 测试无法找到系统 PingFang，使用系统 STHeiti 作为中文回退；实际应用仍采用平台系统字体。

上述渲染可检查视口、明暗主题、大字、滚动及适用的组件操作，但不包含原生标题栏。电脑控制权限仍未授予，真实 macOS 点击、VoiceOver、设备性能和后端读写未完成端到端验收。Android 和 iOS 构建仍需补齐工具链后验证。

## Go 服务端

在新的终端中从仓库根目录进入服务端，执行测试和构建：

```bash
cd App/engine
go test ./...
go build ./...
```

需要启动服务时，在同一目录执行：

```bash
go run ./bin
```

默认配置路径为相对于服务端当前工作目录的 `config.yaml`，因此运行命令应在 `App/engine/` 内执行。目录迁移不改变 `go.mod` 中的模块名称，也不要求修改模块导入路径。

数据库建表脚本位于同目录的 `ddl.sql`。执行脚本前，应根据自己的数据库环境检查内容与目标数据库。
