正文、刻度与元数据的保存链路已修复，客户端回归、服务端事务测试及原生 Mac 双进程保存／冷启动读取均获得通过证据。原生主链路使用真实生产 `EditPage`、gRPC、JWT／Redis 认证与 PostgreSQL 18；首次双进程验证以内存注入测试主密钥，随后补做同一 Debug 包、独立 QA 命名空间下的系统登录 Keychain 跨进程读写，冷启动读取通过。

- 最终标准 Mac Debug 构建与 `codesign --verify --deep --strict` 检查通过；存储配置修复后再次确认静态分析无问题、完整 UIQA 83 项通过。
- 独立备份恢复在第一阶段验收时仍未完成；第二阶段实现与后续证据见[备份恢复验证](备份恢复验证.md)。第一阶段的 83 项回归和媒体未验收结论保留为当时边界。

## 本次修复

| 链路 | 实施内容 |
| --- | --- |
| 编辑器保存与恢复 | 使用版本化 `v1` 载荷统一保存富文本与刻度，兼容旧 Delta 和旧刻度载荷。元数据、Markdown 与刻度变更参与自动保存；保存使用不可变快照并串行处理，离开页面等待保存结果。 |
| 失败保护 | 保存失败保留输入并提供重试；未知载荷或解密失败进入只读保护，避免以空内容覆盖。允许加密空文本，保证主动清空能够保存。 |
| 加密更新 | 更新已有记录复用原数据密钥及原包装密钥字节，每次加密使用新 nonce，避免部分更新使未修改字段无法解密。客户端连接使用实际配置的 `grpcPort`。 |
| 原子性与字段完整性 | 记录、权限与分组变更纳入事务；补齐级别、日期等字段更新并修正筛选列。事务内任一环节失败均回滚。 |
| 幂等创建 | 客户端为一次新建保持稳定 `creationId`，通过 `document-create-id` metadata 传递；重复请求命中同一记录。首次提交期间产生的新编辑内容在首次快照落库后继续补写。 |
| Mac Debug 密钥存储 | 本机没有可用签名身份，ad-hoc Debug 访问默认 Data Protection Keychain 返回 `-34018`。仅 Mac Debug 的 `Storage.macOptions()` 改用独立 `${App.fullAppIdentity}.local-debug` 账号命名空间及 `useDataProtectionKeyChain: false`，写入系统登录 Keychain；Profile／Release 保持原 Data Protection 配置和账号。未修改 entitlements，也不迁移或删除旧 Keychain 内容。 |

本次没有修改 `.proto` 协议或数据库表结构；上述行为调整不代表完成完整安全审计。

Debug Keychain 选择采用插件支持的配置方式，参数名称已对照项目实际使用的 `flutter_secure_storage 9.2.4` 核查。配置背景见插件官方[macOS Keychain 与签名说明](https://github.com/juliansteenbakker/flutter_secure_storage#macos-keychain-sharing-requires-provisioning)。独立 QA 命名空间使用与生产 Debug 相同的选择器完成复核；Debug 与 Profile／Release 不自动共享主密钥，跨构建模式迁移、重新签名后的读取及正式 Profile／Release 的签名与 Data Protection 访问仍待验证。

## 验证结果与证据

环境为本机 macOS Debug 客户端、隔离 Go gRPC 服务、PostgreSQL 18 与 Redis。Flutter 命令在 `App/WhisperingTime/` 执行，Go 命令在 `App/engine/` 对应工程及隔离测试环境执行。临时日志、测试运行环境与截图统一保存于 `TMP/记录可靠性/2026-10-15/`，该目录按仓库约定被 Git 忽略；链接指向本地执行证据，不会随正式文档提交。

本轮实际版本为 Flutter 3.47.7、Dart 3.13.5、Go 1.27.2、PostgreSQL 18.6。Go 工具链与缓存位于任务目录的 `runtime/` 内；本地安装了 PostgreSQL 18、Redis 及其依赖，没有注册后台启动服务。PostgreSQL 集成测试需要显式设置 `WHISPERINGTIME_TEST_POSTGRES_DSN`；未设置时会跳过。本次已指定隔离数据库并获得全部通过结果。

验证结束后已停止临时 gRPC、PostgreSQL、Redis 和 QA 应用，测试数据与日志保留在任务目录。最终的测试、构建、链接、原文一致性及端口检查见[最终核对](../../TMP/记录可靠性/2026-10-15/最终核对.json)。
